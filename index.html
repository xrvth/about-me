01 / Profile

Nice to meet you

Computer science engineering graduate, 4+ years in tech across web maintenance, QA engineering and automation. Until recently on Comscore's AI enabling team.

I've been around computers since I was three. At eight I started poking at game source code out of curiosity and made small mods for The Sims 2 and 3; by ten I was building websites and blogs, and I cut my teeth on Tumblr themes and a lot of HTML and CSS. But the dream was to build Baymax. I did not build Baymax, since it turned out I'm actually terrible at physics, but I do build software. So, close enough.

I came to testing from programming and design rather than the other way round, and the two turned out to feed each other. QA taught me to troubleshoot properly: I find my own bugs before I declare something as finished, I think about the edge cases while I'm still designing, and I write more precisely than I did when I only shipped features. Learning to break things made me better at building them.

So the day-to-day is Python, shell and JavaScript, internal tools built from scratch and designing interfaces, with a tester's habits underneath all of it.

Lately that's meant AI agents: a Claude-based QA assistant that reads Jira tickets and writes structured QA reviews and Zephyr test cases, and a Claude + MCP + Playwright system that turns a bug ticket into a reproducible browser test on its own.

With agents I care as much about the running cost as the output. Getting that Playwright system to persist generated code instead of re-prompting for every click took its repeat runs from ~700k tokens to zero. Cheaper to run, faster to trust, and a lot less water wasted for the same answer.

Where I think AI belongs

I build AI agents for a living and I'm deliberate about where they go. They earn their keep on tedious, repetitive work: reading a hundred tickets, drafting the boilerplate, running the same check for the thousandth time. That is the job I want them doing.

I don't use generative AI for art. Illustration and design are expression, and that part should stay with the person making it. It's a line I hold in my own work and it isn't up for negotiation.

Even inside automation I'd rather reach for it less than more. A lot of what gets called AI automation is a deterministic script wearing a costume, and it usually ends up slower, pricier and less predictable than the plain script would have been. The best decision I made on my Playwright agent was working out which steps never needed a model and taking it out of the loop: repeat runs dropped from about 700k tokens to zero and got roughly ten times faster. Use the model where the task genuinely calls for judgment, not because it's the impressive-sounding option.

Personal · biggest side project

TwisteOptimizer

PythonSQLiteVanilla JSCSSWeb scrapingGPL v3

An offline-first planner for Disney Twisted-Wonderland that answers two questions about your account, not the game in the abstract: is this card worth pulling for me, and would levelling it actually help? ~10k lines, no frameworks and no dependencies. The HTTP server is Python standard library only.

  • Scrapes and joins three sources: 514 cards from the EN wiki, Japanese tier rankings from kamigame, and the official game API for live banners.
  • Matches Japanese card names onto English ones (~99% exact, the rest by a similarity pass scoped per character); anything still unmatched is surfaced rather than guessed at.
  • Three interchangeable scoring models that that disagree on purpose (gap-filling, community tier and exam-output simulation), each showing showing the arithmetic behind it.
  • Team optimizer builds your best five for an exam or a specific story battle, scoring elements that beat the enemy rather than match it.
  • Seven dorm themes, custom form controls, a canvas overlay scrollbar and a full help guide; all motion disabled under prefers-reduced-motion.
  • Hand-authored SVG artwork, with every accent exposed as an RGB triplet so ~60 glows and washes follow the active theme at their authored opacity.

The settings screen separates what's fact from the game, what's someone's opinion converted to numbers, and which constants are just judgement calls, because those are three different kinds of input and a tool that blurs them is lying to you.

Repo goes public soon. Ask me for a walkthrough in the meantime.
